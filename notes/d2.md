# Day 2 — Web Backend Foundations

## Progress

Day 2 moved the chatbot from a terminal-only Python program toward a web application.

Instead of communicating with Ollama directly through a terminal loop, the project now has the foundation for this flow:

**Webpage → FastAPI backend → Ollama → FastAPI response → Webpage**

This is better because the chatbot logic is no longer tied to one terminal interface. A webpage or another application can eventually communicate with it through an API.

## What I Built

- Created a basic FastAPI application.
- Added a `/health` endpoint to confirm that the server is running.
- Learned how FastAPI decorators connect HTTP methods and routes to Python functions.
- Ran the application using Uvicorn with automatic reload during development.
- Began learning how the browser will send requests to the backend using `fetch()`.

## What I Learned

### HTTP Basics

- A **client** sends requests. In this project, the client will be the webpage.
- A **server** receives requests and sends responses. FastAPI is the server application.
- A **request** contains information such as a method, URL, headers, and sometimes a body.
- A **response** contains a status code, headers, and usually a body.

### Methods and Endpoints

- `GET` is normally used to retrieve information.
- `POST` is normally used to send or process data.
- A **route** is a path such as `/health` or `/chat`.
- An **endpoint** is the combination of an HTTP method and a route, such as `GET /health`.

### URLs

A URL can contain:

- Protocol
- Host
- Port
- Path
- Query parameters

For local development, the FastAPI server runs on `localhost` using a specific port.

### JSON and Headers

- JSON is the main data format that the frontend and backend will use to communicate.
- `Content-Type: application/json` tells the receiver that the request body contains JSON.
- Serialization converts a JavaScript object into JSON text.
- Deserialization converts JSON text back into a usable object.

### Asynchronous Requests

- Browser requests take time, so JavaScript handles them asynchronously.
- `await` waits for a request or response body without freezing the entire webpage.
- A successful network response should still be checked for HTTP errors.

### Streams

- Request and response bodies are streams.
- Reading or sending the body consumes that stream.
- A consumed body normally cannot be read or sent again.

### FastAPI and Uvicorn

- FastAPI defines the application, routes, validation, and responses.
- Uvicorn runs the FastAPI application as a local web server.
- Reload mode automatically restarts the server after code changes.

### Input and Output Models

- Input models define the structure of data sent into the API.
- Output models define the structure of data returned by the API.
- These models improve validation, consistency, documentation, and error handling.
