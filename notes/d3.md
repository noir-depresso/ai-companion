# Day 3 - Browser Chat Interface

## Progress

Day 3 moved the chatbot from an API-only backend toward a usable local web chat.

Instead of testing messages only through `/docs` or terminal commands, the project now has the foundation for this flow:

**Browser page -> JavaScript fetch -> FastAPI `/chat` -> Ollama -> FastAPI response -> Browser page**

This is better because the chatbot can now be used through a simple interface instead of manually sending JSON requests.

## What I Built

- Added a static frontend folder under `app/static`.
- Created `index.html` as the main browser page.
- Created `app.js` to handle sending messages and displaying responses.
- Created a CSS file for basic chat layout and separate user/assistant message styling.
- Added a `/` route in FastAPI that serves the chat page.
- Mounted `/static` so the browser can load JavaScript and CSS files.
- Added a loading indicator while Rin is generating a response.
- Added basic error display for failed requests.
- Added Enter-to-send behavior, with Shift+Enter kept for new lines.

## What I Learned

### Static Files

- HTML, CSS, and JavaScript files can be served by FastAPI.
- `FileResponse` can return a specific file such as `index.html`.
- `StaticFiles` maps a URL path such as `/static` to a local folder such as `app/static`.
- The browser requests supporting files separately after loading the main HTML page.

### HTML Structure

- The page uses a main chat container.
- The message list starts empty and is filled by JavaScript.
- The textarea collects the user's message.
- The submit button sends the form.
- Status elements such as loading and error messages can exist in the page while starting hidden.

### JavaScript and Forms

- `document.querySelector()` selects HTML elements so JavaScript can read or update them.
- `addEventListener("submit", ...)` runs code when the form is submitted.
- `event.preventDefault()` stops the browser from reloading the page.
- `fetch()` sends the user's message to the backend.
- `JSON.stringify()` converts a JavaScript object into JSON text for the request body.
- `response.json()` converts the response body back into a JavaScript object.

### Updating the Page

- JavaScript can create new message elements with `document.createElement()`.
- `textContent` safely places message text into the page.
- CSS classes such as `user` and `assistant` control how each message looks.
- Scrolling to `messagesElement.scrollHeight` keeps the newest message visible.

### Loading and Error States

- The input and button are disabled while the model is responding.
- The `hidden` CSS class is toggled to show or hide loading and error messages.
- Failed backend requests can be caught with `try`, `catch`, and `finally`.
- `finally` is useful because it restores the interface whether the request succeeds or fails.

### Keyboard Behavior

- A textarea normally uses Enter to create a new line.
- A chat app can override this so Enter sends the message.
- Shift+Enter can still be used when the user wants a line break.
- `requestSubmit()` submits the form through the normal form submit path.

## Key Terms

Static file, HTML, CSS, JavaScript, DOM, form, submit event, textarea, fetch, JSON, `querySelector`, `createElement`, `textContent`, loading state, error state, `FileResponse`, `StaticFiles`, keyboard event.

## Day 3 Result

By the end of Day 3, the project had a plain browser-based chat window that can send messages to the local FastAPI backend and display Rin's replies.

The chat is still temporary. If the page is refreshed or the backend restarts, the visible conversation is lost. Persistent chat history begins on Day 4 with SQLite.
